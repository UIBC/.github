# Code of conduct

This organisation adopts the **Contributor Covenant, version 2.1** — the canonical text lives at
<https://www.contributor-covenant.org/version/2/1/code_of_conduct/> and is incorporated here by reference.

## What it means in these repositories

- Technical disagreement is expected and welcome. The protocol is young and the spec may be wrong; being wrong politely is how it gets fixed.
- Attack the claim, not the person who made it. No insults, no sarcasm at someone's expense, no "obviously you didn't read".
- No harassment, discrimination, or sexualised attention, in issues, pull requests, discussions, reviews or private channels.
- Publishing someone's private information without permission is not allowed. This includes quoting a private security report in public without consent.
- One specific case in this project: **"this is not a security product" / "you are not a real standard"** is a legitimate argument, not a personal attack. Answer it with evidence, not with volume.

## What is out of bounds here

- Soliciting a verdict. Offering to pay for a PASS, or asking for a review that skips the gate, ends the conversation.
- Presenting a self-run as an independent verification. The ledger counts receipts, not claims.
- Using this organisation's name to imply certification, accreditation or regulatory approval.

## Enforcement

Report a breach to the maintainer through GitHub's private reporting channel on the repository where it happened (Security tab → *Report a vulnerability* is the only private channel this organisation currently has; put "conduct" in the title).

There is one maintainer, so enforcement is best effort and there is no appeal body. Outcomes, in the Contributor Covenant's terms, are correction, warning, temporary ban, or permanent ban, and the reason is stated to the person concerned.

If you cannot accept enforcement by a single person, that is a fair reason not to contribute yet — and it is written here rather than discovered later.
